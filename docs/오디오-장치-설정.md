# 오디오 장치 설정 (macOS)

모드 2는 기타와 목소리를 **서로 다른 하드웨어에서 동시에** 받아야 한다. 기타는 오디오
인터페이스(Scarlett Solo의 악기 잭), 목소리는 다른 마이크(에어팟, 내장 마이크 등)로
들어오는 게 보통이다. 그런데 CoreAudio는 한 번에 기기 하나만 열 수 있다.

입력과 출력을 다른 기기로 지정하는 방법은 **동작하지 않는다**. 실측: 입력을 24kHz 기기,
출력을 48kHz 기기로 잡으면 JUCE가 클럭이 다른 두 기기를 묶지 못하고 조용히 기본
기기(에어팟)로 폴백한다. 화면의 기기 이름이 내가 고른 것과 다르면 이 상황이다.

그래서 **필요한 기기들을 통합 기기(Aggregate Device) 하나로 묶어야 한다.**

## 빠른 길 — 스크립트 하나로 끝내기

아래 "만들기"의 과정을 매번 손으로 하지 않는다. 통합 기기를 만들고, 앱 설정 파일에
기기와 채널을 적어 넣고, 앱을 띄우는 것까지 스크립트가 한다:

```sh
tools/mode2-setup.sh airpods
```

프리셋은 세 가지다(기타는 셋 다 Scarlett Solo 악기 잭).

| 프리셋 | 출력 | 목소리 마이크 | 쓰는 상황 |
|---|---|---|---|
| `airpods` (기본) | 에어팟 | 에어팟 | 소리만 확인. 무선이라 왕복 80ms대 — 연주감 평가엔 부적합 |
| `speakers` | 맥북 스피커 | 에어팟 | 지연이 낮다. 하울링 고리가 생기니 "하울링 억제"를 켤 것 |
| `builtin` | 맥북 스피커 | 맥북 내장 마이크 | 에어팟 없이 확인할 때 |

핵심은 **채널 번호를 사람이 찾지 않는다**는 것이다. 채널 배치는 서브기기 순서가 정하고
그 순서는 기기를 만든 도구가 알고 있으므로, 스크립트가 그 출력을 그대로
`Mode2ChannelMap.xml`에 적는다. 앱은 켜자마자 그 기기·그 채널로 열린다.

앱이 떠 있으면 스크립트가 먼저 닫는다. 앱은 **종료할 때 자기 설정을 저장**하므로, 켜 둔
채로 설정 파일을 고치면 종료하는 순간 예전 값으로 덮어쓰인다.

아래 내용은 프리셋에 없는 구성을 직접 만들거나, 뭔가 어긋났을 때 읽는다.

## 만들기

```sh
cmake --build build --target Mode2AudioDevice
build/Mode2AudioDevice list
```

`list`로 실제 기기 이름을 확인한 뒤, **출력 기기를 맨 앞에** 두고 만든다:

```sh
build/Mode2AudioDevice create "Guitar + AirPods Mic (Mac Speakers)" \
    "MacBook Pro" "AirPods" "Scarlett Solo"
```

이름은 일부만 적어도 찾는다(대소문자 무시). 같은 이름으로 다시 실행하면 기기가 늘지 않고
덮어써진다. 지울 때는 `build/Mode2AudioDevice remove "<이름>"`(또는 `list`에 찍힌 UID).

**서브기기 순서가 곧 채널 순서다.** 출력 기기를 맨 앞에 둬야 출력 ch0-1이 그 기기가 된다.
오디오 인터페이스가 앞에 오면 인터페이스 출력이 ch0-1을 차지해서, 스피커로 내보내려던
소리가 인터페이스의 헤드폰 단자로 나간다.

만들고 나면 도구가 채널 배치를 그대로 출력한다. 위 구성의 결과:

```
  출력 ch0-1  MacBook Pro 스피커
  입력 ch0-0 (앱: 채널 1-1)  YHS의 AirPods Pro
  출력 ch2-3  Scarlett Solo USB
  입력 ch1-2 (앱: 채널 2-3)  Scarlett Solo USB
```

즉 앱 화면에서 **목소리 = 채널 1, 기타 = 채널 3**(Scarlett Solo는 INPUT 1=XLR,
INPUT 2=악기 잭이므로 악기 잭이 채널 3이다).

## 왜 통합 기기가 오히려 유리한가

에어팟은 마이크를 쓰는 순간 HFP로 내려가 단독으로는 24kHz가 된다. 24kHz에서는 블록
하나가 두 배로 길어져(512샘플 = 21.3ms) 제어 갱신이 절반으로 느려진다.

그런데 통합 기기 안에서는 드리프트 보정을 거쳐 **48kHz로 올라온다**(실측 확인). 에어팟
마이크를 쓰면서도 24kHz 저하를 피할 수 있다.

## 소리가 안 날 때 — 먼저 볼 것

**출력 기기 자체가 음소거이거나 볼륨 0인 경우가 가장 흔하다.** 시스템 출력을 에어팟으로
쓰는 동안 내장 스피커는 음소거·볼륨 0으로 남아 있기 쉽다. 이 상태에서는 통합 기기도
앱도 모두 정상인데 소리만 나지 않아서, 라우팅이나 채널 매핑을 엉뚱하게 의심하게 된다.

`create`가 이걸 확인해서 아래처럼 경고한다. 경고가 뜨면 시스템 설정 → 사운드에서 출력
기기를 골라 음소거를 풀고 볼륨을 올린다(메뉴 막대 볼륨은 *기본* 출력 기기에만 적용되므로,
기본 출력이 에어팟이면 내장 스피커 볼륨은 그걸로 안 올라간다).

```
  !! MacBook Pro 스피커 의 볼륨이 0이다 — 소리가 안 난다.
```

그 다음으로는 앱이 Mode 2 화면에 들어가 있는지 본다. 메인 화면에서는 출력이 무음이다.

## 주의

- 스피커 출력 + 열린 마이크는 하울링 고리다. 앱의 "하울링 억제"를 켜고 출력 볼륨을
  낮춰서 시작한다.
- 통합 기기는 시스템 전체에 보이는 기기다. 다른 앱의 기기 목록에도 나타난다.
- 무선 출력(에어팟)은 왕복 지연이 180ms를 넘어 연주감 평가에 쓸 수 없다. 앱 하단의
  지연 표시가 이를 경고한다. 타이밍까지 보려면 유선 출력을 쓴다.

## 앱이 기억하는 것

- `~/Library/VocalGuitarApp/AudioDeviceSettings.xml` — 장치·샘플레이트·버퍼
- `~/Library/VocalGuitarApp/Mode2ChannelMap.xml` — 기타/목소리 채널 (0부터 셈)

앱에서 고른 값이 여기 저장되므로 보통은 손댈 일이 없다. 장치 이름으로 저장되니, 통합
기기를 같은 이름으로 다시 만들면 앱은 그대로 다시 붙는다.
