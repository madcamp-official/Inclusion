# PART 1. 모드 2 — 기타 보코더 모드

## 1. 무엇을 만드는가

사용자가 기타로 멜로디를 단음으로 연주하면서 동시에 노래한다. 시스템은 **지금 기타가 낸 음을 목표 음정으로 삼아, 마이크로 들어온 목소리를 실시간으로 그 음정에 맞춰 변조**해 내보낸다.

```
기타 단음 입력 → 온셋 검출 → 피치 검출 → 안정화 → 목표 음정
마이크 입력   → 활동 감지 → 피치 검출 → 목표와의 차이 계산 → 실시간 피치 시프트 → 출력
```

**이 모드에는 자동 반주, 곡 위치 추적 기능이 없다.** 기타는 소리를 내는 악기가 아니라 **음정 컨트롤러**로만 쓰인다. 스피커로 나가는 소리는 변조된 목소리 하나뿐이다.

## 2. 핵심 설계 결정

| 결정 | 내용 | 이유 |
|---|---|---|
| M2-1 | 목표 음정은 **현재 기타 음정**이다 | 사용자가 실시간으로 통제해야 함 |
| M2-2 | 사용자 목소리의 **음색은 유지**한다. 음정만 옮긴다 (채널 보코더 방식이 아니다) | 출력이 본인 목소리로 들려야 함 |
| M2-3 | 기타 피치가 사라져도 목표를 즉시 버리지 않는다 | 목표 소실 시 음정이 튀면 음질이 깨짐 |
| M2-4 | 무엇이든 확신이 없으면, 짧게 유지한 뒤 **드라이(원본 목소리)로 감쇠**한다 | 틀린 음정을 강하게 내보내는 것보다 사용자 본인 음정이 낫다 |
| M2-5 | 사용자에게 특정 연주 타이밍(예: "노래보다 기타를 먼저 짚어라")을 요구해서 문제를 해결하지 않는다 | 사용감이 최우선. 엔지니어링으로 해결한다 |
| M2-6 | 기타 소리는 스피커로 내보내지 않는다 | 기타는 컨트롤러이지 악기 출력이 아니다 |
| M2-7 | 모니터링은 헤드폰 없이 **스피커**로 한다 | 실제 사용 환경 |

## 3. 목표 음정 결정 (기타 경로)

7.5절의 안정화 상태 기계(IDLE → ATTACK → COLLECT → STABLE → COAST)를 그대로 사용한다.

- 기타 신호가 아예 없으면 COAST를 거쳐 목표를 해제한다
- 목표 변경 시 시프트 램프를 적용한다 (즉시 점프 금지)
- 목표를 잃었을 때: 일정 시간(HOLD) 동안은 직전 목표 유지 → 이후 일정 시간(FADE) 동안 강도를 0으로 감쇠 → 드라이 통과 (M2-4)

## 4. 보정량 계산 (목소리 경로)

```python
def compute_correction(vocal_midi_float, target_midi, strength):
    if target_midi is None or vocal_midi_float is None:
        return 0.0
    diff_st = target_midi - vocal_midi_float
    if abs(diff_st) > MAX_CORRECTION_ST:      # 옥타브 오류로 간주, 보정 포기
        return 0.0
    return strength * diff_st
```

- `strength`(음정 추종도)는 **최대에 가깝게** 설정한다. 목표는 "교정"이 아니라 "일치"이므로, 기존 계획서에 있던 "1.0은 로봇처럼 들린다"는 이유로 강도를 낮추는 설계, 그리고 "비브라토 보존"을 이유로 한 데드존은 **채택하지 않는다**
- 시프트량이 급변하면 아티팩트가 크므로, 목표 전환 시 램프를 적용한다

## 5. 지연 구조

새 음을 짚었을 때 목소리가 어떻게 나오는지는 **성질이 다른 두 개의 경로**로 이해해야 한다.

```
오디오 경로 (목소리가 소리로 나오기까지):
  마이크 → A/D → 입력버퍼 → [피치 시프터] → 출력버퍼 → D/A → 스피커

제어 경로 (시프트량이 정해지기까지):
  기타 → 온셋 → 음정 검출 → 안정화 대기 → 시프트량 확정
```

목소리는 오디오 경로의 시간에 나오고, 시프트량은 제어 경로의 시간에 확정된다. 그래서 **새 음을 짚은 직후 아주 짧은 순간(합쳐서 50ms 미만)은 이전 음정으로 나오다가 새 음정으로 미끄러져 들어간다.** 이 정도 길이는 음 시작부의 자연스러운 스쿱(scoop)처럼 들리며 별도 조치가 필요 없다.

다만 노래가 기타보다 먼저 시작되면 그 구간이 그만큼 늘어난다. **이 문제는 연주 요령이 아니라 다음 두 장치로 해결한다 (M2-5).**

**장치 ① — 목소리 경로에 짧은 인위적 지연을 둔다.**
목소리를 온셋 검출까지 걸리는 시간만큼만 늦춰서 내보낸다. (안정화 대기 전체에 맞추지 않는다 — 그러면 드문 최악의 경우 때문에 항상 지연 비용을 치르게 된다.) 이렇게 하면 정상적인 경우 잘못된 음정 구간이 크게 줄어든다.

**장치 ② — 그래도 남는 구간은 M2-4(확신 없으면 드라이)로 흡수한다.**

## 6. 시프터 선택

| 후보 | 지연 | 음색 보존 | 통합 난이도 | 채택 |
|---|---|---|---|---|
| **SoundTouch** (WSOLA) | 낮음 | 시프트량에 비례해 나빠짐(작은 시프트에서는 양호) | 낮음 — 바인딩 존재 | **1순위** |
| **자체 TD-PSOLA** | 가장 낮음 | 좋음 | 중~상 | 2순위 |
| Signalsmith Stretch / Rubber Band (위상 보코더 계열) | 높음 | 좋음, 다만 특유의 번짐 | 중 | 제외 |

근거: 헤드폰 없이 스피커로 모니터링하므로(M2-7) 목소리 지연 비용이 크다. 사용자는 멜로디를 따라 부르므로 실제 시프트량은 몇 반음 이내로 작은 경우가 대부분이라 SoundTouch의 약점(포먼트 이동)이 크게 드러나지 않는다. 통합 난이도도 가장 낮아 일정 리스크가 작다.

- GATE-2(피치 시프트 게이트) 통과 조건: **작은 시프트량(몇 반음 이내)에서 본인 목소리로 들리는가**를 기준으로 한다. 큰 시프트에서의 음질은 판단 기준에서 제외한다 (큰 시프트는 애초에 검출 오류로 간주해 보정을 포기하기 때문)

## 7. 되먹임(하울링)과 마이크 오염 대응

헤드폰이 없으므로 처리된 목소리가 스피커 → 마이크로 되돌아가는 구조다. 다음을 필수 대책으로 둔다.

물리 배치

- 지향성 마이크(카디오이드 이상)를 근접 사용
- 스피커는 마이크의 지향성이 가장 둔한 방향에, 마이크보다 앞에 두지 않는다
- 스피커 음량은 하울링 시작점보다 충분히 낮게 제한

소프트웨어

| 방법 | 목적 |
|---|---|
| 캘리브레이션 시 하울링 임계 측정 → 마스터 게인 상한 자동 설정 | 하울링 방지 |
| 목소리 음정 검출 신뢰도가 낮으면 시프트량을 갱신하지 않고 유지/감쇠(M2-4)로 전환 | 기타 소리가 마이크로 새어 들어와 검출을 흔드는 것을 차단 |

리스크로 관리할 항목: **되먹임에 의한 하울링 / 처리음 재처리**(확률 중, 영향 대. 조기 경보: 출력 피크가 지속 상승하거나, 목표 음정 변화 없이 출력 음정이 한 방향으로 계속 이동).

## 9. UI 표시 (S6 모드 2 화면)

```
┌─────────────────────────────────────────────────────┐
│  기타      C4       ← 목표 음정                     │
│  내 목소리 B3 (-92 cent)                            │
│  보정 후   C4 (-18 cent)   추종도 [========] 90%    │
└─────────────────────────────────────────────────────┘
```

- 기타 음정 / 내 목소리 음정 / 보정 후 음정을 항상 함께 표시한다
- 반주·위치 진행 바·다음 코드 등 **반주 관련 표시는 없다**
- "다음 멜로디 음" 안내를 넣을지는 선택 사항이다. 넣는다면 정밀한 위치 추적이 아니라, 순서대로 "다음에 칠 음은 이것"이라고 세어서 보여주는 정도로 충분하다 (참조 멜로디의 음 순서만 사용, 실시간 정합 불필요)

## 10. 파라미터

아래 값들은 모두 **아직 튜닝 전이며, 실제로 소리를 들으며 정한다.** 본문·다른 절에는 구체적 숫자를 적지 않고, 이 표만을 기준으로 삼는다.

| 파라미터 | 조절 대상 | 올리면 | 내리면 | 상태 |
|---|---|---|---|---|
| 온셋 최소 간격 (모드 2) | 너무 가까운 온셋을 무시하는 간격 | 오검출 감소 | 반응성 증가 | 미정 |

| 기타 음정 소실 후 유지 시간(HOLD) | 기타가 끊겼을 때 이전 목표를 붙잡는 시간 | 안 끊김 | 다음 음 전환 빠름 | 미정 |
| 강도 감쇠 시간(FADE) | HOLD 이후 강도를 0으로 낮추는 시간 | 부드러운 복귀 | 빠른 복귀 | 미정 |

| 시프트 램프 | 목표 전환 시 미끄러지는 시간 | 부드러움 | 빠르게 붙음 | 미정 |
| `MAX_CORRECTION_ST` | 이 이상 차이나면 보정 포기(옥타브 오류로 간주) | 넓게 허용 | 오류에 안전 | 미정 |

## 11. 이 사양에서 제외된 것 (원래 계획서에 있었으나 삭제)

다음은 **모드 2에서 완전히 제거한다.** 반주 자동 재생 기능 자체를 빼기로 했기 때문이다.

- 곡 위치 추적기(ScoreFollower) 및 관련 알고리즘 전체
- 반주 렌더러(BackingRenderer), 반주 오디오 버스, 반주 관련 믹서 설정
- 반주 제작 파이프라인 (코드 패드·베이스·드럼 합성 작업). **곡 데이터 제작 시간에서 반주 제작 항목(곡당 약 30분)을 뺄 수 있다**
- 반주 관련 리스크·게이트: 위치 추적 실패 리스크, 위치 추적 게이트, 템포 추정·표류 관련 항목
- 기타 모니터 출력 (믹서의 `guitar_monitor` 버스)
- "참조 멜로디 MIDI를 실시간 목표 결정에 쓴다"는 개념 자체 — 목표는 오직 실시간 기타 검출로만 정해진다

곡 데이터 규격(10장) 중 `melody.mid`/`melody.json`은 모드 2의 실시간 동작에는 더 이상 필요 없다. 9절의 "다음 멜로디 음" UI 안내를 넣기로 하면 그 용도로만 참고용으로 남긴다.

# PART 2. 모드 1 — 보컬 추종 모드 (수정 부분)

> 모드 1은 친구분 담당 파트다. 아래는 이번에 논의하며 방향을 바꾼 부분만 다룬다. 연주 활동 감지(8.2절), 보컬 표현 매핑(8.5절), 실패 대응(8.6절) 등 나머지는 원본 계획서 그대로 유효하다.

## 1. 무엇이 바뀌는가

**원래 계획서**: 곡은 내부 Song Clock이 정한 속도로 흘러가고, 기타 연주는 그 위에서 보컬을 켜고 끄고 볼륨만 조절한다. 기타를 멈춰도 곡은 계속 흐른다.

**수정**: **보컬(반주)이 사용자의 연주를 따라온다.** 사용자가 빠르게 치면 반주도 그에 맞게 진행되어야 한다. 원래 계획서의 방향은 정반대였다.

## 2. 바뀌지 않는 이유 — 왜 단순히 "따라가게" 바꿀 수 없는가

모드 1의 보컬은 미리 만들어 둔 오디오 파일(프레이즈 WAV)을 재생하는 방식이다(D1-3, 유지). 오디오 파일은 빨리 재생하면 음정이 같이 올라간다. 음정을 지키면서 속도만 바꾸려면 실시간 타임 스트레칭이 필요한데, 이는 모드 2의 피치 시프터와 같은 급의 무거운 처리라 14일 일정에 부담이 크다.

## 3. 채택한 방식 — 프레이즈 단위 재정렬

곡 전체를 실시간으로 늘였다 줄였다 하지 않는다. 대신 **각 프레이즈(가사 한 소절)가 시작되는 시점만 사용자의 연주에 맞춰 다시 잡는다.** 프레이즈 안에서는 원래 속도 그대로 재생한다.

```
사용자 연주 → 프레이즈 시작 신호 감지 → 예정된 프레이즈 시작 시점과 비교
  → 허용 범위 안이면: 그 시점에 맞춰 프레이즈 재생 시작
  → 허용 범위 밖이면: 재정렬하지 않고 원래 스케줄대로 진행
```

사람이 부르는 노래는 어차피 프레이즈 단위로 호흡이 끊기므로, 경계에서만 다시 맞춰도 "내 연주를 따라온다"는 느낌은 충분히 난다.

## 4. 정의가 필요한 세부 사항 (친구분 확인 필요)

- **무엇을 보고 프레이즈 시작을 판단할 것인가.** 모드 1의 입력은 코드 스트로크이므로 모드 2 같은 멜로디 매칭은 쓸 수 없다. 후보: 온셋 타이밍, 코드 전환 검출, 또는 둘의 조합
- **재정렬 허용 범위.** 예정 시점에서 얼마나 벗어난 것까지 "같은 프레이즈의 시작"으로 인정할지
- **프레이즈 내부에서 어긋났을 때.** 프레이즈 중간에는 재정렬하지 않는다(끊기므로). 어긋난 채로 끝까지 가고 다음 프레이즈 경계에서 다시 맞춘다
- **겹침·공백 처리.** 앞 프레이즈가 재생 중인데 다음 프레이즈가 당겨지는 경우, 반대로 공백이 생기는 경우
- **곡 시계와의 관계.** 화면에 표시되는 코드·가사 진행은 곡 시계를 기준으로 한다. **프레이즈만 옮기고 곡 시계를 그대로 두면 화면과 실제 들리는 보컬이 어긋난다.** 프레이즈가 재정렬되면 곡 시계도 함께 움직여야 한다

## 5. 지연은 문제가 아니다

모드 1의 보컬은 파일 재생이라 소리 자체의 지연은 10ms 미만으로 무시할 수 있다. 조정이 필요한 것은 지연이 아니라 "언제 프레이즈를 시작할지"라는 타이밍 판단 로직이다.

| 항목 | 대략 | 성격 |
|---|---|---|
| 연주 시작 → 보컬 페이드인 | 수십 ms ~ 150ms | 온셋 검출 + 게인 램프 |
| 연주 정지 → 보컬 페이드아웃 시작 | 200~300ms | 의도된 값. 짧으면 스트로크 사이 공백마다 보컬이 끊긴다 |
