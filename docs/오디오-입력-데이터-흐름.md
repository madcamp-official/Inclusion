# 오디오 인터페이스로 들어온 소리가 어떤 형식으로, 어떻게 처리되는가

이 문서는 **마이크·기타에서 나온 아날로그 신호가 오디오 인터페이스를 거쳐 앱 코드 안에서
어떤 자료형이 되고, 어디로 흘러가는지**만 정리한다. 알고리즘(피치 검출·시프트) 자체의 설계는
[모드1_모드2_최종사양서](모드1_모드2_최종사양서.md)를 보면 된다.

기준 코드는 모드 2(기타 보코더) 경로다.

> **Windows에서 작업한다면** [오디오-입력-데이터-흐름-AI용.md](오디오-입력-데이터-흐름-AI용.md)의
> 7~9절을 보라. 빌드 방법, 환경 설정 체크리스트, macOS와의 차이(특히 **Rubber Band가 없어
> 기본 시프터가 SoundTouch로 바뀌는 문제**)가 정리되어 있다. 아래 본문의 경로 표기는 macOS 기준이다.

## 0. 한눈에 보는 전체 경로

```

                                    ▼                                              ▼
                           ch[기타 인덱스]                                 ch[목소리 인덱스]
                     온셋 → 피치 → 안정화 = 목표 음정            유입상쇄 → 부스트 → 피치검출 → 피치시프트

                              D/A → 스피커/헤드폰                 3채널 진단 WAV(녹음 켠 경우)
```

## 1. 장치를 여는 쪽 — 몇 채널을 요청하는가

[MainComponent.cpp:29](../src/main/MainComponent.cpp:29)

```cpp
setAudioChannels(8, 2, savedAudioState.get());
```

- **입력 8채널을 "여유 있게" 요청**한다. 실제로 열리는 채널 수는 장치가 정한다(2in 인터페이스면 2).
  8을 요청하는 이유는 macOS의 **통합 기기(Aggregate Device)** 때문이다. 오디오 인터페이스와
  내장 마이크(또는 에어팟)를 하나의 통합 기기로 묶으면 입력 채널이 3개 이상이 되고,
  그중 어느 채널이 기타이고 어느 게 목소리인지는 사람이 골라야 한다.
- **출력은 2채널**(스테레오)이다. 다만 내용물은 좌·우가 완전히 같은 모노다.
- 앱 안의 "오디오 장치 설정" 다이얼로그는 `AudioDeviceSelectorComponent(deviceManager, 1, 8, 1, 2, ...)`
  ([MainComponent.cpp:90](../src/main/MainComponent.cpp:90)) — 입력 1~8, 출력 1~2 범위에서 고를 수 있다.
- macOS는 앱을 껐다 켜면 시스템 기본 입력으로 되돌아가므로, 장치 선택 상태를 XML로 저장/복원한다:
  `~/Library/VocalGuitarApp/AudioDeviceSettings.xml` (Windows는 `%APPDATA%\VocalGuitarApp\`)

**샘플레이트와 블록 크기는 앱이 정하지 않는다.** 장치가 정해서 알려주고, 앱은
`prepareToPlay(samplesPerBlockExpected, sampleRate)`로 그 값을 받아 내부 버퍼를 다시 잡는다
([MainComponent.cpp:288](../src/main/MainComponent.cpp:288)).

## 2. 콜백으로 들어오는 데이터의 정확한 형식

오디오 스레드가 주기적으로 `getNextAudioBlock(const juce::AudioSourceChannelInfo&)`를 부른다
([MainComponent.cpp:299](../src/main/MainComponent.cpp:299)). 그 안의 `bufferToFill.buffer`가 실제 소리다.

| 항목 | 값 |
|---|---|
| 자료형 | `float` (32비트 부동소수) |
| 값의 범위 | `-1.0 ~ +1.0` (0dBFS = 1.0). 인터페이스의 24비트 정수 샘플이 이미 정규화되어 들어온다 |
| 배치 | **비인터리브(non-interleaved)**. 채널마다 별도의 연속 배열 — `buffer.getReadPointer(ch, startSample)` |
| 한 번에 들어오는 길이 | `bufferToFill.numSamples` (= 장치의 버퍼 크기, 보통 128/256/512) |
| 시작 오프셋 | `bufferToFill.startSample` (0이 아닐 수 있으므로 항상 더해서 읽어야 한다) |
| 샘플레이트 | 장치가 정한 값. 44.1k / 48k가 보통이고 **에어팟은 24kHz**가 되기도 한다(4절 참고) |
| 채널 순서 | 인터페이스의 물리 입력 순서. 예) Scarlett Solo = ch0 XLR 마이크, ch1 기타 잭 |

### ⚠ 가장 중요한 함정: 입력 버퍼와 출력 버퍼가 같은 메모리다

JUCE의 이 콜백은 **같은 버퍼에 입력이 담겨 오고, 거기에 출력을 덮어써서 돌려준다.**
그래서 습관적으로 맨 앞에서 `clearActiveBufferRegion()`을 부르면 **입력을 읽기도 전에 지운다.**
코드가 입력을 먼저 스크래치 배열로 복사해 두는 이유가 이것이다
([MainComponent.cpp:301](../src/main/MainComponent.cpp:301), [:319](../src/main/MainComponent.cpp:319)).

```cpp
std::copy(guitarRead, guitarRead + numSamples, guitarInputScratch.begin());
std::copy(vocalRead,  vocalRead  + numSamples, vocalInputScratch.begin());
// ↑ 이 복사 뒤에야 outL/outR로 buffer의 채널 0,1에 덮어쓸 수 있다
```

또 하나: 오디오 스레드에서는 **메모리 할당·락·파일 I/O를 하면 안 된다.** 스크래치 배열은
`prepareToPlay`에서 미리 잡고, 녹음은 `ThreadedWriter`(락 없는 FIFO)로 넘긴다.

## 3. 어느 채널이 기타이고 어느 게 목소리인가

하드코딩하지 않는다. 장치마다 물리 배선이 다르기 때문이다.

- 화면의 콤보박스에서 "기타 채널 / 목소리 채널"을 고른다 ([Mode2Screen.cpp:234](../src/ui/mode2/Mode2Screen.cpp:234))
- 고른 값은 `std::atomic<int>`로 오디오 스레드에 전달되고
  (`guitarChannelIndex`, `vocalChannelIndex` — 기본 0, 1),
  `~/Library/VocalGuitarApp/Mode2ChannelMap.xml`에 저장된다
- 실제 읽을 때는 `jlimit(0, lastChannel, ...)`으로 클램프한다. 장치가 바뀌어 채널 수가 줄어도
  범위 밖을 읽지 않게 하기 위해서다

채널 배선이 의심스러우면 `-DMODE2_DIAGNOSTIC_LOG=1`로 빌드한다. 매 24블록마다 **모든 입력 채널의 RMS**를
로그로 찍어서, "채널 순서가 바뀐 것"과 "마이크가 기타 소리를 줍는 것"을 구분할 수 있다
([MainComponent.cpp:328](../src/main/MainComponent.cpp:328)).

## 4. 샘플레이트가 왜 중요한가 (에어팟 함정)

분석 창 크기가 **샘플 수**로 정의되어 있으면, 샘플레이트가 절반이 될 때 창의 **시간 길이가 두 배**가 된다.
에어팟을 입력으로 쓰면 장치가 24kHz로 열리는 경우가 있어서 이 문제가 실제로 발생했다.

그래서 창 크기를 현재 샘플레이트에 비례해 다시 계산한다
([Mode2Params.h:167](../src/params/Mode2Params.h:167)):

```cpp
scalePitchWindowForSampleRate(2048, sampleRate)  // 48kHz 기준 2048샘플 ≒ 42.7ms 유지
```

48kHz면 2048샘플, 24kHz면 1024샘플 — 어느 쪽이든 **실제 시간은 약 42.7ms로 고정**된다.

## 5. 각 채널이 실제로 어떻게 소비되는가

### 5-1. 기타 채널 (= 음정 컨트롤러, 소리로는 안 나감)

`GuitarTargetTracker::processBlock(guitarIn, numSamples)` 하나로 묶여 있다.

1. **온셋 검출** — 블록 RMS 에너지 플럭스가 EMA 베이스라인의 1.6배를 넘고, 직전 온셋에서 50ms 이상 지났을 때
2. **피치 검출** — MPM(McLeod Pitch Method, NSDF 자기상관). 탐색 범위 **70~1200Hz**
   (6번줄 개방현 E2 82Hz ~ 1번줄 12프렛 E5 659Hz를 덮는다)
3. **반음 양자화 + 히스테리시스** — 검출된 "순간 주파수"가 아니라 "연주한 음표"로 바꾼다(±0.65반음)
4. **상태 기계 안정화** — IDLE → ATTACK → COLLECT → STABLE → COAST. 출력은 `targetMidi`와 `fadeGain`

기타 소리 자체는 출력 버퍼에 절대 섞이지 않는다(설계 결정 M2-6).

### 5-2. 목소리 채널

[Mode2Controller.cpp:116](../src/mode2_guitar_vocoder/Mode2Controller.cpp:116) 순서 그대로:

1. **기타 유입 상쇄** — 목소리 마이크에 새어 들어온 기타를, 기타 채널을 참조 신호로 삼아 NLMS 적응 FIR(256탭)로 뺀다.
   *부스트 전에* 거는 이유는, 부스트 뒤에 걸면 사용자가 슬라이더를 움직일 때마다 학습한 경로 이득이
   어긋나기 때문. 기본값은 **꺼짐**(헤드폰 + 라인 입력 환경에서는 뺄 게 없다)
2. **입력 부스트** — 단순 스칼라 곱(기본 2.0). 내장 마이크는 레벨이 너무 낮아 피치 검출 신뢰도에 못 미친다
3. **피치 검출** — 같은 MPM. 단 탐색 범위는 **100~450Hz**로 좁다.
   넓으면 배주기 피크(한 옥타브 아래)·배음 피크(한 옥타브 위)를 잡아 출력이 옥타브 단위로 튄다
4. **3탭 미디언 필터** — 검출 지터를 걸러낸다. 지속되는 옥타브 변화는 통과시킨다
5. **딜레이 버퍼** — 제어 경로와 오디오 경로 정렬용. 현재 정렬량은 **0ms**
   (측정해 보니 이 검출기의 추정값은 창 중앙이 아니라 창의 최신 끝에 대응했다 — [Mode2Params.h:46](../src/params/Mode2Params.h:46))
6. **피치 시프트** — Rubber Band / SoundTouch / WORLD 중 선택. 보정량 = (기타 목표 MIDI + 옥타브 이동) − 내 음정

### 5-3. 출력

```cpp
outL[i] = outR[i] = clamp(shifted[i] * outputGain, -0.95, +0.95);
```

좌·우가 완전히 같은 모노다. `outputGain`은 캘리브레이션 상한 × 사용자 볼륨 × 하울링 덕킹 × 트립 게이트.
마지막 리미터(±0.95)는 어떤 경우에도 폭주하지 않게 하는 안전장치다.

## 6. 진단 녹음 파일 형식

같은 연주를 두 번 할 수 없기 때문에, 파라미터 A/B 비교를 하려면 **입력까지 그대로 남겨야** 한다.

| 항목 | 값 |
|---|---|
| 포맷 | WAV, **24비트 정수**, **3채널** |
| 샘플레이트 | 장치의 현재 샘플레이트 그대로 |
| ch0 | 기타 입력 (원본, 손대기 전) |
| ch1 | 목소리 입력 (**부스트 전**, 유입 상쇄 전) |
| ch2 | 당시 최종 출력 |
| 저장 위치 | `~/Library/VocalGuitarApp/recordings/mode2_YYYYMMDD_HHMMSS.wav` |

이 파일을 `Mode2Offline` 도구에 넣으면 **앱과 똑같은 `Mode2Controller`에 같은 블록 크기로** 다시 통과시킬 수 있다.
연주는 고정되고 파라미터만 변수로 남으므로 비교가 성립한다.

```bash
./build/Mode2Offline_artefacts/Debug/Mode2Offline in.wav out.wav --octave=-1 --shifter=rubberband
```

주요 옵션: `--glide` `--boost` `--volume` `--octave` `--gate` `--bleed` `--block` `--lookahead` `--shifter`

## 7. 요약 — 친구가 기억해야 할 6가지

1. 인터페이스에서 들어오는 건 **채널별로 분리된 float32 배열**, 값은 −1~+1, 길이는 블록 크기.
2. **입력 버퍼 = 출력 버퍼**다. 읽기 전에 지우면 안 되고, 쓰기 전에 복사해 둬야 한다.
3. 채널 번호는 장치마다 다르므로 **하드코딩하지 않고 UI에서 고른 뒤 XML에 저장**한다.
4. 샘플레이트는 장치가 정한다. **샘플 수로 정의된 창은 반드시 샘플레이트로 스케일**해야 한다.
5. 기타 채널은 **음정 정보만** 뽑는 컨트롤러이고, 스피커로는 목소리 하나만 나간다.
6. 디버깅은 3채널 WAV 녹음 + `Mode2Offline` 오프라인 재현이 정석이다.
